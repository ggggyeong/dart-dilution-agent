## 0. 범위

- 대상 공시: 주요사항보고서(유상증자결정) 문서코드 11306 · 11308
- 기간: 2023-04-17 ~ (지금 원본만. 2023-04-17 ~ 2025-12-31 1,180건 + 2026년 414건 = 1,594건)
- 저장: 공시 당시 코스피 · 코스닥 상장사만 (`market_at_filing`)
- 제외: 비상장 회사 (비표준 양식 80518 포함), 코넥스. 원본 파일은 지우지 않고 DB에만 넣지 않음
- 범위 밖 (지금 안 함): 현재 주가, 회사 재무, 증권신고서 본문, 대상자 재무, 순환 지분, BW · EB · 합병
- 날짜: 공시일은 DART 목록 API의 `rcept_dt`를 그대로 쓴다 (장 마감 뒤 접수 등은 다음 영업일로 잡힘, 2026년 유상증자의 4.7%). 접수일은 접수번호 앞 8자리로 알 수 있어 따로 저장하지 않는다.

## 2. 시험지 (5번 `CI_MTH`로 판별)

| CI_MTH | 시험지 | 6번 이후 표 (ACLASS) | 기타 투자판단 |
|---|---|---|---|
| 1 · 2 · 3 | 주주배정 계열 | `STK_ASN_INC` (6~23번) | 24번 |
| 5 | 일반공모 | `OTH_PUB_INC` (6~19번) | 20번 |
| 6 | 제3자배정 | `THD_ASN_INC` (6~19번) | 20번 + 부속 표 |

- 1~5번(`CST_CNT`)과 기타주식(`STO_ETC`)은 세 시험지 공통.
- **번호가 아니라 칸 코드(ACODE)로 읽는다.** 같은 칸도 시험지마다 번호가 다름 (예: 납입일 12번 · 9번 · 10번).
- 주주우선공모(2)는 번호 체계가 달라 같은 이름의 항목으로 찾는다. 신주인수권 양도(`NST_GV_YN`) · 증서 상장(`WRNT_LST_YN`) · 1주당 배정(`NEW_ASN_CNT`) 칸이 양식에 없다.
- CI_MTH 4(직접공모)는 받은 데이터(2026년 전체 + 2023~2025 표본)에 없어 구현하지 않는다.

## 3. 처리 순서

1. 공시 목록에서 사건 판별: 새 사건 / 기존 사건의 정정 / 철회
2. 최신 정정본 선택 (날짜 · 가격은 정정으로 바뀜)
3. 철회면 상태만 갱신하고 멈춤 (값은 철회 전 마지막 공시 것 유지)
4. `CI_MTH`로 시험지 결정
5. 아래 표의 칸을 코드로 읽음
6. 글에서만 나오는 값은 LLM이 읽음 (6장의 3가지, 근거 문장 함께)
7. 저장

## 5. 규칙

| 규칙 | 내용 |
|---|---|
| 철회 | 최신 정정본의 신주 수 · 가격 칸이 모두 "-"이고 정정 사유에 "철회" → status = 철회 (정정본을 넣을 때 적용) |
| 최신 값 | 공시마다 한 줄씩 저장하고, 질문할 때 as_of 시점까지의 최신 버전을 고른다. 정정 신고 표의 "정정 전"은 직전 버전 값임 |
| "-" | 자금 용도 · 할인율의 "-"는 0. 그 밖의 칸은 null ("원문 '-'"과 "못 읽음"은 확인 자료에서만 나눠 센다) |
| 한 칸에 "-"와 숫자 | 숫자를 쓴다 |
| 할인율 부호 | 숫자만 저장 (회사마다 할인을 10 또는 -10으로 적음). 제3자배정은 `CST_ISS_VAL` > `CST_STD_VAL`이면 할증(음수) |
| 할인율 null | 제3자배정에서 기준주가(`CST_STD_VAL`)가 "-"이면 null (거래정지 등으로 기준주가 없음). 기준주가가 있으면 "-"는 0 |
| 가격 | 주주배정은 확정가 · 예정가 칸 중 하나만 채워짐. 둘 다 보고 price_status를 정함 |
| 주주우선공모 (CI_MTH 2) | right_sale = 불가, shares_per_share = null |
| 발행 주식 종류 (stock_type) | 보통: 보통주만 → 그대로 저장. **우선: 우선주(RCPS 등)만 → 주식 종류별 값(new_shares · price · price_status · price_confirm_date · discount_rate · listing_date)은 비워 둠**, 기존 보통주 수 · 자금 용도 · 대상자 · 참여 방식은 저장. 혼합: 보통주 값만 저장 (희석률은 보통주만), 우선주 몫은 rights-v5(2026-10-24 fix2)부터 other_new_shares · other_price에 저장해 조달액에만 더함. 우선주는 "보통주 몇 주로 바뀌나"(전환 조건)를 읽어야 제대로 저장할 수 있고, 이는 CB와 같은 방식이라 CB 작업 때 만드는 코드로 다시 읽어 채운다 (2026년 원본 414건 중 우선 28, 혼합 1) |
| 납입 방식 (payment_type) | 값 5가지: 현금 / 빚→주식 / 현물 / 섞임 / 불명 (출자전환과 상계는 "빚→주식" 하나로 — 회사도 "출자전환(채무상계)"처럼 섞어 씀). **규칙은 두 가지만**: ① CI_MTH 1·2·3·5 → 현금 (제목에 "(출자전환)"이 있으면 빚→주식) ② CI_MTH 6이고 코드 없는 자유 서술에 현금 외 단어(출자전환 · 상계 · 현물 · 대용 · 회생채권 · 대여금)가 하나도 없음 → 현금. **나머지는 모두 LLM** — `PIN_EXT_YN` = Y도 포함 (채권을 현물출자 형식으로 넣는 경우가 있음, 예: 지엔코). 단어검사 오탐("~할 수 있음" 선택지 문구, "해당없음", 정관 `RULE` 칸)도 LLM이 판단. 2026년 실데이터에서 현금 외 납입은 제3자배정에서만 나옴 |
| 맞물림 검사 | 신주 수 × 가격 ≈ 자금 용도 합계 (1% 이내), 대상자 주식 수 합 = 신주 수, 날짜 순서(기준일 → 청약 → 상장), 상장 예정일 > 공시일. 앞의 두 검사는 payment_type이 현금이고 stock_type이 보통일 때만 (현금 외 · LLM 대기는 새 돈이 없거나 대상자 표에 일부만 적힘, 혼합 · 우선은 우선주 몫이 빠져 있음). "대상자 일부만 기재"는 칸을 만들지 않고 확인 자료에만 표시 |

## 6. LLM 사용처 (3가지 일, 칸 6개)

| 값 | 시험지 | 실제로 쓸 모델에게 주는 입력 | 출력 |
|---|---|---|---|
| payment_type | 제3자배정 (규칙으로 못 정한 것) | **원문 전체** (extract-v3~). v1~v2는 20번 글 · 목적 표 · 4번 자금 용도 · 13번 현물출자 칸 · 17번 면제 사유 · 대상자 이름과 관계 · 자유 서술만 잘라 넣었으나, 대상자 표 거래내역 칸 · 연도별 자금 사용 표 같은 단서가 빠졌다 (아스트) | 현금 / 빚→주식 / 현물 / 섞임 / 불명 + 근거 문장 |
| discount_rate | 주주배정 | 자유 서술 전체 (코드 없는 `<P>`, 길이 제한 없음 — 사실상 24번 글) | 숫자 + 근거 문장. 1차 · 2차가 다르면 예정발행가액(1차) 값. 없으면 null |
| right_sale_period | 주주배정 (right_sale = 시장) | 위와 같은 글 (할인율과 함께 판정하면 한 번만 넣음) | 시작일 · 종료일 + 근거 문장. 원문에 날짜가 없으면 null (예: 삼성바이오로직스 20260828000001은 "최소 5거래일 이상 상장"만 있음 → 정정본 단계에서 채움) |

- **실제 판정 모델: `claude-opus-5-5`, effort medium, 프롬프트 `extract-v2`** (`llm/extractor.py`). 판정 출처 `llm:claude-opus-5-5:extract-v2`.
  - 결정 근거 (extract-v1, 정답표 135건 대비): Haiku 5.5 납입 방식 79/95 · Sonnet 5.5 87/95 · Opus 5.5 95/95. 운영 호출이 연 약 80건(LLM 대기 + 주주배정)이라 비용 차이가 작아 정확도 우선.
  - extract-v2 재확인: 납입 방식 95/95, 할인율 45/45, 권리 매도 기간 44/44, 근거가 입력에 없음 0 (실제 비용 $3.02).
- 할인율 · 권리 매도 기간을 소제목 단위로 자르면 하위 번호에서 끊겨 정답 문장이 빠진다 (extract-v1에서 리츠 서식 포함 7건, Opus도 틀림). 24번 머리말은 대부분 코드 칸(`ISS_FUNC`) 안에 있어 `<P>`에서 찾을 수 없으므로 자유 서술 전체를 넣는다 (주주배정 45건 2,470~7,400자).
- 프롬프트 원칙: 입력에 붙인 [이름표]는 근거에 넣지 않음. 납입 방식을 직접 말하는 문장이 없어도 정황으로 판단할 수 있으면 값을 고르고 정황 판단(`payment_indirect`) 표시, 불명은 정황도 없을 때만. 정답표에 맞추려는 사례별 설명(예: 회생 M&A)은 넣지 않는다.
- 근거 문장이 **모델에 넣은 글**(원문에서 잘라낸 것)에 실제로 있는지 코드가 확인한다. 없으면 값을 쓰지 않는다.
- **정답표용 Opus에게는 원문 전체**를, **실제 판정 모델에게는 위 표의 입력만** 준다. 정답용 LLM 설정(`llm/answer_key.py`)은 실제 판정용과 따로 관리한다.
- Opus 정답표 대상: LLM 대기 전부 + 주주배정 전부 + 제3자배정 `rule:no_keyword` 표본 50 + 주주배정 · 일반공모 `rule:ci_mth` 표본 10. 표본 60건이 모두 현금이라 규칙 유지.
- 2023~2025 새 표본 재검증 (`validate_fresh.py`, 처음 보는 공시 60건, Opus 원문 전체 정답표 $2.32): 할인율 30/30, 권리 매도 기간 26/26, 납입 방식 28/30. 불일치 2건은 원문 자체가 애매함 — 아스트 20240722000152 (정답표 빚→주식 / 실제 섞임: 대상자에 채권자가 아닌 최대주주 1,082,000주가 있어 실제 판정 쪽이 더 맞아 보임), 페니트리움바이오 20250616000371 (정답표 현금 / 실제 현물: 현물출자 칸 '예' · 가액 = 조달 총액인데 재산 종류 없음, 자금 용도 운영자금 · 납입처 증권사). 정답표도 같은 모델이라 함께 틀릴 수 있음.
- extract-v3 (납입 방식만 원문 전체, 할인율 · 권리 매도 기간은 v2와 같아 v2 결과 유지): 2026년 135건 납입 방식 95/95 · 할인율 45/45 · 권리 매도 기간 44/44, 새 표본 납입 방식 29/30 (불일치 페니트리움바이오는 정답표가 틀림 — 같은 날 타법인주식양수결정에 "현대바이오사이언스 보통주 388,392주로 대용납입" → 현물). v2 → v3 바뀐 것 206건 중 2건: 아스트 섞임 → 빚→주식 (고쳐짐), 카프로 20240328001867 섞임 → 현금 (틀려짐 — 대상자 표에 투자자 현금 1.4억 주 + 채권은행 출자전환 2,100만 주가 함께, 섞임이 맞음).
- 납입 방식 검사 (`scripts/flag_payment.py`, `validate/payment_flags.py`): LLM 판정이 "현금"인데 ① 대상자 이름에 "출자전환" · "상계" ② 발행가 산정 근거(자유 서술 "<6. 신주의 발행가격> … 산정근거" ~ 다음 머리말, + 7-3번 칸)에 "2)" (괄호 "(2)"는 제외) → `review/payment_flags.csv`. 카프로(v3 현금)를 두 조건 모두로 잡음. 2026-10-17 기준 LLM 현금 36건 중 0건.
- extract-v4 (2026-10-17, 돌리지 않음): 지시문에 "상계·대용납입이라도 상계되는 채권이 같은 거래에서 자산(주식·부동산 등)을 사며 생긴 매매대금이면 현물, 그 전부터 있던 빚(대여금·차입금·예전 사채 원금)이면 빚→주식" 추가 (CB cb-v2와 같은 규칙). 지금 DB 값은 v2 · v3 그대로 (`apply_llm_results.py` VERSIONS).
- 사람 판정: `manual/payment.csv` (저장소에 보관). `apply_llm_results.py`가 LLM 결과보다 우선 적용, payment_source = `manual:<결정일>`, payment_evidence = 근거. 표를 다시 만들어도 다시 적용된다.
- 실제 판정은 `scripts/run_llm.py` (남은 대상만, 결과 `llm_runs/<버전>/`).
- DB 반영: `scripts/apply_llm_results.py`. `build_rights_tables.py`로 표를 다시 만들면 LLM 값이 지워지므로 이것도 다시 돌린다.

- 시험지별 칸 채움률 (상장사 · 철회 제외 기준). 현재 확인: 주주배정 신주 수 · 기존 주식 수 거의 100%, 할인율 26/26
- 원본 30건 시범 (시험지별 10건): 원본 XML과 따로 대조(사용자)해 490칸 중 484칸 일치, 추출 오류 없음. 검토 의견은 v1.1에 반영
- 맞물림 검사 (5장). 걸린 공시는 **값을 고치지 않고 원문대로 저장**하고 정정본 단계에서 다시 본다. 원본 414건에서 7건: 대상자 주식 수 칸에 금액이 적힘 2(루트K, 케스피온), 대상자 주식 수 "-" 3(지니틱스, SK하이닉스 ADR, 아이오케이이엔엠), 대상자 합 ≠ 신주 수 1(크라우드웍스), 신주 수 × 가격 ≠ 자금 용도 합계 1(헝셩그룹). LLM 반영 후 현금으로 정해진 사건에서 1건 추가: 딥커머스 20260721001140 대상자 8명 합 7,374,852주 ≠ 신주 수 36,874,260주 (정확히 5배, 원문 표 그대로). 2023~2025 원본 1,180건에서 원문 쪽 27건 (발행가 칸 오기 7, 대상자 주식 수 칸에 금액 3, 대상자 합 ≠ 신주 수 14, 기타 3) — 원문대로 둠 (사용자)

- 30건 정답 대조 (시험지별 10건, 정정 포함): 칸별 일치율
